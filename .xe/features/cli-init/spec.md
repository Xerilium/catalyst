# Feature: CLI Init

## Purpose

Initialize Catalyst in a project from the command line and hand off to AI-driven product setup.

## Scenarios

### FR:init: Project Initialization

Developer needs a single command to initialize Catalyst in their project so that it is ready to use and they know how to start product setup, regardless of which package manager they use.

- **FR:init.@command** (P1): Interface: `catalyst init`
  > - @req FR:cli-engine/cli.dynamic
- **FR:init.@playbook** (P1): Interface: `src/resources/cli-commands/init.yaml`
  > - @req FR:playbook-yaml/structure
- **FR:init.legacy** (P1): Command MUST delete command files generated by earlier Catalyst versions so that plugin skills don't appear twice
  > - @req FR:playbook-actions-controls/composition.playbook-action
  - **FR:init.legacy.files** (P1): Command MUST delete generated command files `.claude/commands/catalyst/*.md`, `.cursor/commands/catalyst/*.md`, and `.github/prompts/catalyst.*.prompt.md`
    > - @req FR:playbook-actions-scripts/script.context-injection
  - **FR:init.legacy.gitignore** (P2): Command MUST remove the Catalyst `.gitignore` sections and files written by command generation
    > - @req FR:playbook-actions-git/gitignore-edit.remove
  - **FR:init.legacy.directories** (P3): Command MUST remove emptied `catalyst` command directories
  - **FR:init.legacy.preserve** (P1): Command MUST NOT delete files outside the generated patterns
- **FR:init.positioning** (P2): Command MUST describe itself as initializing Catalyst in the project
- **FR:init.handoff** (P2): Command MUST output a closing message instructing the user to add the Catalyst plugin to their AI tool and run `/catalyst:init` to set up product context
  > - @req FR:init-workflow/workflow.@ai-skill
- **FR:init.idempotent** (P2): Command MUST be safe to run repeatedly without corrupting prior installs

## Architecture Constraints

- **No code CLI**: Command logic MUST be expressed as a YAML playbook composed of broadly-useful native actions; no install-specific TypeScript code path.
- **Composition over coupling**: Per-feature install workflows are invoked via the `playbook` composition action; `cli-init` does NOT know the internals of any feature's install logic.
