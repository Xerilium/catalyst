# Explore: Impeccable Design Skill Lessons

Draft for review. No specs or code changed. Moved from the "Design system / creative eye" section of [212](https://github.com/Xerilium/catalyst/pull/212) and redone against first-hand research of Impeccable and the agents from [228](https://github.com/Xerilium/catalyst/pull/228).

**Prompted by**: Roland uses Impeccable in allyte-web, and it duplicates Catalyst artifacts. Question: What in Impeccable works and what does not, which parts are new ideas Catalyst can learn from, and how can Catalyst do them better?

**Sources**: [impeccable.style](https://impeccable.style), [`pbakaus/impeccable`](https://github.com/pbakaus/impeccable) (Apache 2.0, about 107k stars, engine v0.1.22 at time of writing), its issue tracker, and Roland's [allyte-web](https://github.com/allytehq/allyte-web) usage (`.impeccable/`, `PRODUCT.md`, `DESIGN.md`, `scripts/projectionDocs.test.ts`).

**Credit**: Ideas below come from Impeccable by Paul Bakaus (Apache 2.0), which started from Anthropic's `frontend-design` skill. Any Catalyst file built from these ideas is rewritten in Catalyst voice, credits Impeccable, and copies no text.

## Findings

### What Impeccable is

- One skill with 23 commands plus a deprecated alias, in five groups: steer (`bolder`, `quieter`, `distill`, `colorize`, `typeset`, `layout`, `animate`, `delight`, `overdrive`), review (`critique`, `audit`), finish (`polish`, `harden`, `clarify`, `adapt`, `optimize`, `onboard`), iterate (`live`, `generate`), and set up (`shape`, `init`, `document`, `extract`)
- Context files at the repo root: `PRODUCT.md` (product truth) and `DESIGN.md` (visual system with a token frontmatter), plus `.impeccable/` state: config, `design.json` sidecar, surface briefs, critique snapshots, ignore list
- A Rust engine binary (detector with 62 rules, browser capture, comp measurement, font matching, decision page server), shipped for about 20 agent hosts
- A design hook that runs the detector after each UI file edit
- Four shipped subagents: finish reviewer, documenter, asset producer, manual edit applier

### What works

| Mechanism                                                                                                                                                                                                                                                    | Why it works                                                                                                                         | Evidence                                                                        |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| **Refuse list**: named AI-default patterns (same-size icon cards as page structure, hero-metric template, eyebrows above headings, gradient text, decorative glass, side-stripe borders, hard offset shadows, glyph icons, mono as costume, modal by reflex) | Names the exact tells, so the agent can recognize and rewrite them. "The brief wins" rule stops it from fighting an explicit request | Biggest single lever on generic output; the README before/after is built on it  |
| **Craft floor**: checks on the rendered result, not intentions (contrast, measure, type scale, spacing rhythm, states, copy)                                                                                                                                 | Turns taste into checks a reviewer can pass or fail                                                                                  | Roland's critiques cite these checks directly                                   |
| **Browser surfaces** check: themed selection, caret, scrollbars, focus rings, tabular numerals                                                                                                                                                               | Cheap, rarely done, and a clear sign of a built page                                                                                 | Unique to Impeccable among the design prompts reviewed                          |
| **Mode per surface**: Persuade, Operate, Read, Experience                                                                                                                                                                                                    | Scales ambition to the job: bold on a landing page, restraint in app UI. Chosen per surface, not per product                         | Stops "bold" advice from breaking dashboards                                    |
| **Specificity test**: could an unrelated product reuse this unchanged?                                                                                                                                                                                       | One question that catches generic work                                                                                               | Gave the allyte-web homepage verdict ("category-interchangeable")               |
| **Isolated review**: fresh-context reviewer with no build transcript; design review finishes before detector output is shown                                                                                                                                 | Removes builder optimism and anchoring                                                                                               | Roland's critiques ran as two isolated agents and found issues the build missed |
| **Bounded finish**: one batched screenshot round, fix batch, confirm round, two rounds max; four derived verdict words (`recapture`, `rebuild`, `fix`, `ship`)                                                                                               | Stops endless polish loops; the verdict comes from the findings, not mood                                                            | Prevents the screenshot-per-tweak token burn                                    |
| **Evidence check first**: blank, wrong, or half-loaded captures force a recapture before any review                                                                                                                                                          | A review on bad screenshots binds nothing                                                                                            | Rarely seen elsewhere; cheap                                                    |
| **Decided choices are not re-raised**                                                                                                                                                                                                                        | Keeps reviews from re-proposing settled choices                                                                                      | Roland's critique listed his `design-decisions.md` choices as "not raised"      |
| **Steering verbs**: `bolder`, `quieter`, `distill`                                                                                                                                                                                                           | Gives users words for vague asks ("make it pop") and points a narrow playbook at one target                                          | Most-used surface in the docs and README                                        |
| **Deterministic detector** as edit hook, CLI (`--json`, `--github`), and browser overlay                                                                                                                                                                     | No model needed; catches tells while the agent still has context                                                                     | 62 rules; exit codes for CI                                                     |

### What does not work

| Problem                     | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Second source of truth**  | `PRODUCT.md` and `DESIGN.md` must sit at the root by filename ([119](https://github.com/pbakaus/impeccable/issues/119), [202](https://github.com/pbakaus/impeccable/issues/202)). In allyte-web, `PRODUCT.md` is 260 lines restating an 82-line `.xe/product.md`; `DESIGN.md` is 424 lines restating `tokens.css`. Roland wrote `projectionDocs.test.ts` and `designDoc.test.ts` only to keep the copies honest, and one copy already pointed at a moved path                                                                                                                     |
| **Duplicate decision log**  | `.impeccable/critique/ignore.md` restates `design-decisions.md`; critique snapshots duplicate the GitHub issues Roland filed from them                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Review comes too late**   | allyte-web's homepage scored 21/32 and "category-interchangeable" after it was built with the skill installed. Direction in a side file does not bind the spec or plan, so the build lands generic and the review finds it afterward                                                                                                                                                                                                                                                                                                                                              |
| **No link to requirements** | Findings name files and heuristics, never FRs. Nothing traces a design promise to a test or a spec                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Weight and fragility**    | 4,500 files, a native binary, a 291 MB plugin ([107](https://github.com/pbakaus/impeccable/issues/107)). The top-reacted issues are install failures ([857](https://github.com/pbakaus/impeccable/issues/857), [691](https://github.com/pbakaus/impeccable/issues/691), [871](https://github.com/pbakaus/impeccable/issues/871), [1341](https://github.com/pbakaus/impeccable/issues/1341)), an antivirus flag on the Windows binary ([740](https://github.com/pbakaus/impeccable/issues/740)), and Windows hook breaks ([848](https://github.com/pbakaus/impeccable/issues/848)) |
| **Safety defaults**         | Hooks run outside model approval and can download the engine on first edit. Live mode's Apply can fall back to running `codex` or `claude` with approvals and sandbox off. Neither fits Catalyst's defaults                                                                                                                                                                                                                                                                                                                                                                       |
| **Prompt bloat**            | `new-work.md` paragraphs run past 1,000 words of procedure. The comp-led path says smaller models stall at its hero gate, so it is frontier-only. High token cost per run                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Detector noise**          | False positives on brand tokens, quoted fonts, `var()` fallbacks, closed `<details>` ([428](https://github.com/pbakaus/impeccable/issues/428), [882](https://github.com/pbakaus/impeccable/issues/882), [1001](https://github.com/pbakaus/impeccable/issues/1001)); Roland's homepage critique lists three false-positive groups                                                                                                                                                                                                                                                  |
| **Network dependency**      | A new design fetches visual directions from the impeccable.style catalog even with telemetry off                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

### What is uniquely innovative

| Idea                                                                                                                                                                                                                                               | Why it is new                                                                            |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| **Calibration against model priors**: names the few looks AI output clusters around (cream ground, serif display, terracotta accent; near-black with neon; editorial hairlines; neobrutalist) and has per-model blocks for each model's known bias | Treats the model's default as a known bias to correct, not a style choice                |
| **Randomized direction** (`concept-seed`): the agent lists 7 directions from the audience's world, a seeded roll picks which reach the user, catalog challengers compete, and the category standard stays as a quiet "standing exit"               | Breaks mode collapse on purpose; keeps the user's choice real                            |
| **Discipline donation**: a losing challenger donates one discipline (not its look) to the winning direction, written as a named line                                                                                                               | Makes the winner stronger without blending styles                                        |
| **Measured comp contract**: when a comp exists, the build is a state machine whose gates measure the screen against the comp (region boxes, font fingerprint match, cap height in px)                                                              | Admits models cannot judge their own visual fidelity, and replaces judgment with numbers |
| **Direction contract** in the surface brief, with a FINISH line ("unreviewed and undocumented is unfinished")                                                                                                                                      | A short, durable exit condition that later sessions reload                               |
| **Rule IDs in prose plus behavior tests**: each rule in the skill text has an ID; LLM scenario tests run against three vendors and fail when the agent stops following the loading contract                                                        | Treats prompt text as tested code                                                        |
| **Design system written from the build**: `DESIGN.md` is written at finish by a documenter agent, not before                                                                                                                                       | A rulebook written first gets defended against reality                                   |

## Analysis

### What Catalyst already has that Impeccable lacks

| Catalyst asset                                                                              | Impeccable equivalent       | Catalyst edge                                    |
| ------------------------------------------------------------------------------------------- | --------------------------- | ------------------------------------------------ |
| `.xe/product.md`                                                                            | `PRODUCT.md`                | Already the source; no copy needed               |
| `.xe/standards/design.md`, owned by `creative-director` (228)                               | `DESIGN.md`                 | Points at tokens in code instead of copying them |
| Feature `design-decisions.md`                                                               | `critique/ignore.md`        | Decisions carry rejected options and rationale   |
| `creative-director` agent: reviews the rendered result, Nielsen, WCAG 2.2 AA, verdict (228) | Finish reviewer, critique A | Owns direction and review in one role            |
| Spec FRs with `@req` traceability                                                           | Direction contract          | Promises become requirements a test can cite     |
| Playbook phases, rollouts, execution modes                                                  | Build-phase state machine   | Already gates create, change, and fix            |
| `catalyst check`                                                                            | Detector CLI                | Can check doc drift deterministically            |

So the gap is not a second tool. It is four things Catalyst does not yet ship: the Refuse list and craft floor as a standard, a bounded review step in the feature workflow, direction captured before the spec, and a way to diverge from the category default.

### Change from 212's draft

- **Location**: 212 proposed a new `.xe/design.md`. 228 has since shipped `.xe/standards/design.md` owned by `creative-director`. Use that; drop `.xe/design.md`
- **Reviewer**: 212 proposed a generic fresh-context reviewer subagent. Use `creative-director` instead, started fresh with an evidence packet. It already requires the rendered result and gives a verdict
- **Divergence**: 212 dropped `concept-seed` entirely. Keep the idea at low cost (below), drop the dice, catalog, and telemetry

### How Catalyst improves on each idea

| Impeccable idea       | Catalyst version                                                                                                                                                                                                                                                                                                   | Better because                                                                            |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| Context files         | `.xe/product.md` and `.xe/standards/design.md` only. `design.md` names the token file and never copies values. `catalyst check` rule: the token path in `design.md` exists                                                                                                                                         | One source; the check replaces Roland's two projection tests                              |
| Refuse list, floor    | Shipped `src/resources/standards/ui-craft.md` (like `auq.md`): Refuse list, craft floor, browser surfaces, model-prior calibration, specificity test, mode table. Product-agnostic, about 60 lines, no per-model blocks. Project `design.md` may override a line with a stated reason                              | Same lever at a fraction of the tokens; loads only on UI work                             |
| Direction contract    | UI features carry direction in the spec: a `ui` FR group (first viewport, primary action, signature interaction, mode) plus `design-decisions.md` for the chosen world. Spec and plan read `design.md` and `ui-craft.md` when `ui: true`                                                                           | Shifts direction left of the build (fixes the 21/32 problem); review findings cite FR IDs |
| Divergence            | On Persuade or Experience surfaces with no settled world: `creative-director` names the category rut, proposes 3 directions from the audience's world outside it, plus the category standard labeled as such; one AUQ. Autonomous modes pick the strongest non-rut option and log it. No dice, catalog, or network | Keeps the anti-collapse benefit; no binary, no telemetry, works on any model              |
| Discipline donation   | One line in the divergence step: name what the runner-up does better and raise the pick to match                                                                                                                                                                                                                   | Free; the idea is the value, not the machinery                                            |
| Isolated review       | New `feature-ui-review.md` action: build an evidence packet (screenshots, spec, `design.md`, `ui-craft.md`, `design-decisions.md`), check evidence validity first, start `creative-director` fresh (no transcript), get findings before any detector output, then merge                                            | Reuses the 228 agent; anti-anchoring and evidence check come free                         |
| Bounded finish        | One capture round, one fix batch, one confirm round, stop. Verdict derived: `recapture` (bad evidence), `fix` (findings), `ship` (none). No browser tool: skip with a note, never silently                                                                                                                         | Same bound; three words fit Catalyst's Approve/Request changes                            |
| Decided choices       | Reviewer reads `design-decisions.md`; no ignore file                                                                                                                                                                                                                                                               | Already the decision log                                                                  |
| Findings archive      | Unfixed findings go to the feature's `feedback.md` or a GitHub issue with FR refs; screenshots in gitignored `.xe/runs/`                                                                                                                                                                                           | No critique archive to drift                                                              |
| Detector              | Do not build one. After 212's hook engine ships, a repo may add an external detector (Impeccable's CLI included) as a `feature.closure:gate` hook that hands JSON to the review                                                                                                                                    | Repos that want it get it; Catalyst stays light and safe                                  |
| Design from the build | `creative-director` updates `design.md` from the built result at closure when a new world shipped                                                                                                                                                                                                                  | Same lesson, existing owner                                                               |
| Behavior tests        | Out of scope here. Worth its own explore: rule IDs in playbook text plus LLM scenario tests, building on `@req` traceability                                                                                                                                                                                       | Catalyst playbooks have the same "agent stopped following the contract" risk              |
| Steering verbs        | Not now. `/catalyst:change` with a plain request covers it; revisit if users ask for named design verbs                                                                                                                                                                                                            | Avoids 20 new commands                                                                    |

### Dropped

| Dropped                                                                   | Why                                                                    |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Root `PRODUCT.md`, `DESIGN.md`, `design.json`, token sync tests           | Second source of truth                                                 |
| `.impeccable/` state, critique archive, `ignore.md`                       | `design-decisions.md`, `feedback.md`, and issues cover them            |
| Dice roll, direction catalog, telemetry                                   | Network and binary dependency; the cheap version keeps the value       |
| Comp-led measured build, font fingerprinting, image generation, live mode | Frontier-only, binary-bound; revisit only if comps become common       |
| Hooks outside approval, sandbox-off fallback                              | Unsafe default                                                         |
| Per-model calibration blocks                                              | Maintenance cost per model; the generic calibration carries most value |

### Risks

- **Browser dependency**: The review needs a screenshot tool. Without one it degrades to a source-only review, stated in the output (matches `FR:agents/creative-director/agent.review.visual.source-only`)
- **Subjective findings**: One round cap and decided-choice suppression limit churn
- **Divergence fatigue**: Limited to Persuade and Experience surfaces with no settled world; extensions inherit the world
- **Licensing**: Rewrite and credit in `ui-craft.md`; no pasted text

## Recommendation

Absorb Impeccable's ideas into Catalyst's existing artifacts and the 228 `creative-director` agent. Do not ship or shell out to Impeccable.

1. **Ship `ui-craft.md`** first: the Refuse list, craft floor, and calibration are the most value per token and need no workflow change
2. **Add the bounded review** to `create`/`change` Phase 3 (and `fix` when rendered UI changes), run by a fresh `creative-director`
3. **Shift direction left**: design interview at `init`/`blueprint` writes `.xe/standards/design.md`; UI specs carry a `ui` FR group; divergence step on open Persuade surfaces
4. **Later**: `catalyst check` token-path rule; optional external detector via 212's hooks; a separate explore on behavior tests for playbooks

Rationale: Impeccable's own result on allyte-web shows review alone is late and a side-file source of truth costs real upkeep. Catalyst already owns product truth, decisions, traceability, and a design reviewer, so it can ship the floor and the review loop as text, and put direction in the spec where the build must honor it.
